日期：2026-06-17

范围：主系统 fixed DAG 报告链路，以及后续 sandbox 中真实外部 agent wrapper 的报告材料增强。

原始 Phase 1-8 不改变 `runtime_bindings.json`，不设置 `live_verified=true`，不设置
`invoke_enabled_by_default=true`。Phase 9 在用户明确批准后只切换两个 L4 行到
`external_compute_default`，并把 `live_verified=true` 限定为 L4
`/v1/agent/compute` runtime smoke 证据。所有阶段都不把 `/compute` 证据当成
`/invoke` 证据，不把 default-off demo bridge 当成生产默认路径，也不把 placeholder
agent 当成真实完成。

## 核心判断

最终中文报告像模板，根因不是单纯 prompt 不够好，而是进入报告链路的 agent 研究材料太薄。
报告生成器只能读到 summary、stance、confidence、少量 evidence 时，LLM 或 fallback 模板都会
自然变成固定报告格式。

第一阶段采用保守方案：不新增大而全外部协议，先把已经存在于 `agent_conclusion_v1` /
`dimension_conclusion_v1` / `risk_conclusion_v1` / `macro_conclusion_v1` 中的 public-safe
材料投影到报告输入包。

## 报告材料约定

主系统优先读取四类材料：

1. `domain_metrics`
   领域核心指标，例如估值桥、合理价值区间、模型票数、风险分、宏观 regime、成员数量。

2. `drivers`
   结论驱动材料，例如方法假设、模型投票表、top features、rubric 表、成员权重、降权原因。

3. `data_quality`
   可信度边界，例如数据时点、缓存、覆盖率、缺失组件、反前视、合成语料声明。

4. `research_points`
   agent 自己基于确定性材料生成的可报告化研究判断：
   `claim`、`support`、`interpretation`、`decision_implication`、`caveat`。

这些字段必须 bounded、public-safe，并且不能包含 endpoint、secret、raw provider response、
raw external JSON、traceback 或内部推理草稿。

## L3 与 LLM 边界

L3 composite 的核心融合不交给 LLM。

- 确定性融合核心负责 `stance`、`gate`、`risk_score`、`dimension_weights`、member weights、
  confidence 和 status。
- LLM 只能作为默认关闭的语言解释/冲突归纳层，读取 public-safe L2/L3 材料后生成
  commentary 或 `research_points`。
- LLM 解释层不能覆盖 deterministic fusion 数值，不能把 placeholder/partial 成员包装成真实
  complete evidence。

因此后续 L3 改造方向是：先让 deterministic L3 输出成员权重、冲突、降权和边界；如需 LLM，
只用于解释这些已确定结果。

## 阶段计划

### Phase 1：主系统报告材料层

目标：

- adapter 投影 `domain_metrics`、`drivers`、`data_quality`、`research_points`。
- `report_input_bundle_v1.agent_evidence_bundle` 保留 L2/L3 详细材料。
- fallback 报告优先展开 `research_points`，再显示 evidence、metrics、drivers、quality。
- fallback 报告只展开有 public-safe 材料或 error 状态的 L2；无可读证据的 placeholder/pending
  L2 保留在 `report_input_bundle_v1` 和 workflow trace 中，但正文只汇总缺失覆盖，不逐条当作
  研究材料渲染。
- L3 quality summary 区分 complete、partial、error、available。
- demo bridge 将风险 L2 `provenance.risk_score` 安全透传给 `risk_composite` upstream。
- LLM report synthesis 增加 secret-free provider preflight。
- graph/smoke runner 支持显式 `fixed_dag_as_of`。

验收：

- 主系统相关单测通过。
- 不改 runtime binding 和 live flags。
- 不调用 endpoint。

### Phase 4：L3 composite 解释层

四个 L3 不改融合算法，只增强解释材料：

- `value_composite`：估值分歧、成员权重、fair-value range、主导因子。
- `market_composite`：技术/资金/舆情成员信号、降权原因、短中期冲突。
- `risk_composite`：gate、risk_score、成员风险贡献、partial 成员影响。
- `macro_composite`：regime、value/market 调权依据、缺失宏观成员影响。

LLM 只能作为默认关闭的 language explanation / conflict summary 层，不能成为融合算法。

当前进度（2026-06-17）：

- 主系统 deterministic L3 builder 已能从本轮已有 L2 输出生成 bounded report material。
- `value_composite` / `market_composite`：
  - 只对 `complete` / `partial` 且具备可读方向的成员赋权。
  - 权重按成员 confidence 归一化；缺失、pending、placeholder 成员权重为 0。
  - L3 confidence 会按成员覆盖率折扣，避免一个真实 L2 被误读成完整维度综合。
- `risk_composite`：
  - 只读取风险维 L2，不读取 `sentiment_company_radar`。
  - 基于可用成员 `risk_score` 形成 `pass` / `manual_review` / `veto` gate。
  - 成员缺失或缺少 `risk_score` 时记录覆盖率和边界，不把缺失当成低风险证明。
- `macro_composite`：
  - 没有可用宏观成员时仍保持 `pending_implementation` / `not_evaluated`。
  - `value` / `market` 权重保持 0.5 / 0.5，不在宏观证据不足时主动调权。
- L3 provenance 会输出 `member_weight_summary`、`domain_metrics`、`drivers`、
  `research_points`、`data_quality`，并进入 `agent_evidence_bundle_v1` 和 fallback
  中文报告。
- `risk_composite` 额外保留成员级 `member_boundary_summary`：把风险 L2 的 warnings、
  模型版本边界、缺失文本等 caveat 提升到 L3 `drivers`、`research_points` 和
  `data_quality`。这不改 `risk_score`、`gate` 或成员权重，只避免 L3 压缩后最终报告看不见
  成员边界。
